# Next.js App Router

Compile notebook HTML before the Next build. Keep the manifest on the server and place its generated assets under the site's public directory at the URL used as `--asset-base`. Load it with `readDocument` from `marimo-blog/node`, then pass it to `MarimoArticle` from `marimo-blog/react`. Import `marimo-blog/styles.css` in the root layout or global CSS entry.

The renderer is server-compatible; individual outputs hydrate without turning the entire article into a client component. Its default header uses the document title, date and description. Supply a custom `header` when the host owns additional metadata, brand or links; it replaces the default inside the renderer's aligned slot. Use host-owned classes for that content, and public tokens on a host ancestor for theming—not internal selectors, marimo export classes, or a `.prose` wrapper around the article. See the [token recipe and ownership matrix](theming.md).

Eligible source folds inline after its cell; `code` controls its initial visibility. Published code examples fold independently. Neither hiding source nor disabling JavaScript makes included source private. The renderer centers prose at a 42rem default measure and allows wider figures. Contents starts closed in server HTML and, in auto mode, opens as a sticky right rail on wide article containers after hydration; closing it reclaims the rail. The host supplies the page canvas; a separate figure surface can frame author-owned charts without recoloring them.

Ship each manifest with its matching assets and run `marimo-blog check` against the actual deployment URL base and metadata. Do not expose authoring paths or private files. Python and marimo are needed to create the export, not for the Next build or default reader experience. The repository includes an App Router example and packed-package build check. See [React](react.md) and [security](security.md).
