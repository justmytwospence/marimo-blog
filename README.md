# marimo-blog

Compile executed [marimo](https://marimo.io/) exports into native React articles: server-rendered prose and saved outputs, with narrowly scoped browser enhancements. Ordinary articles never start Python, Pyodide, or a notebook server.

**Pre-release:** implementation and local verification are available; an npm release has not yet been published.

marimo-blog is an independent community project, not an official or endorsed marimo product.

## Two-stage publishing

1. Author and execute a trusted notebook in its own environment. Export official static HTML.
2. Compile the completed export into a validated JSON document and content-hashed assets.
3. Render the document with `MarimoArticle`. Site builds consume those artifacts, not Python.

```sh
marimo-blog inspect notebook.html
marimo-blog build notebook.html --metadata post.yaml --out content/post.marimo.json --assets public/notebooks/post --asset-base /notebooks/post
marimo-blog check content/post.marimo.json --assets public/notebooks/post --asset-base /notebooks/post --metadata post.yaml
```

```tsx
import { readDocument } from "marimo-blog/node";
import { MarimoArticle } from "marimo-blog/react";
import "marimo-blog/styles.css";

export default async function Post() {
  const document = await readDocument("content/post.marimo.json");
  return <MarimoArticle document={document} />;
}
```

The example is a server component; browser-only hosts can load JSON and call `parseDocument` from `marimo-blog`.

## Boundaries

- Official exporter versions **0.25.0, 0.25.1, 0.25.2**, Node **22+**, React **18.3.1 or 19**.
- Saved prose, MathML, images, tables, tabs, accordions, carousel panels, callouts, statistics, and JSON trees.
- Lazy Plotly/Vega specs; figures over 5 MiB require reader action. Table search/sort/download use captured rows only.
- Python-backed controls show saved values and an explicit notice. Unknown widgets fail strict compilation unless acknowledged for their cell.
- Reviewed script output loads near the viewport in an opaque-origin sandbox. It never executes in the parent page.
- Optional official WASM exports open on a separate page. Their packages, data, and runtime still need independent testing.

Eligible source folds inline after its cell; published code examples and structured results start expanded. Local native disclosures work without JavaScript. Article-scoped view switches (under the header and in the contents rail) coordinate available categories, show mixed states, and reset to defaults; contents defaults to responsive auto. See the [presentation defaults](docs/react.md), [output catalog](docs/outputs.md), [compatibility](docs/compatibility.md), and [security model](docs/security.md). Folding or hiding source is not privacy: review every published output and asset.
